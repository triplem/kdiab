= kdiab-measures Operations Guide
:author: kdiab team
:toc: left
:toclevels: 3

== Overview

`kdiab-measures` is the primary health measurement store for the kdiab platform. It persists CGM readings, BGM readings, blood pressure, weight, and pulse measurements. It runs on port 8080 and is the highest-data-volume service in the platform — CGM devices typically write one record every 5 minutes per patient.

== Configuration

All configuration is provided via environment variables (override the defaults in `application.conf`).

=== Required Variables

|===
| Variable | Description | Example

| `JWKS_URL` | Keycloak JWKS endpoint for JWT verification | `http://keycloak:8080/realms/kdiab/protocol/openid-connect/certs`
| `JWT_DOMAIN` | JWT issuer domain | `http://localhost:8081/realms/kdiab`
| `JWT_AUDIENCE` | Expected `aud` claim in JWTs | `measure`
| `JDBC_URL` | PostgreSQL JDBC URL | `jdbc:postgresql://postgres:5432/kdiab-measures`
| `DB_USER` | PostgreSQL username | `kdiab_measures`
| `DB_PASSWORD` | PostgreSQL password | _(from secrets manager)_
|===

=== Optional Variables

|===
| Variable | Default | Description

| `PORT` | `8080` | HTTP listen port
| `JWT_REALM` | `kdiab-measures` | Keycloak realm name (cosmetic; not validated)
| `CORS_ALLOWED_ORIGINS` | `http://localhost:3000` | Comma-separated allowed CORS origins
| `DB_POOL_SIZE` | `10` | HikariCP maximum connection pool size
| `DB_RUN_MIGRATIONS` | `false` | Run Liquibase migrations on startup. Set `true` only in test/local envs; production uses the `liquibase-measures` container.
| `APP_INIT_DATABASE` | `true` | Connect to the database on startup. Set `false` for test environments without a real DB.
| `LOGGING_SUPPRESS_HEALTH_CHECKS` | `true` | Suppress `GET /healthz` and `GET /readyz` from access logs
| `JSON_PRETTY_PRINT` | `false` | Pretty-print JSON responses (development only)
| `SWAGGER_ENABLED` | `false` | Serve Swagger UI at `/swagger`
| `OTEL_SERVICE_NAME` | — | OpenTelemetry service name (set to `kdiab-measures`)
| `OTEL_TRACES_EXPORTER` | `none` | OTLP trace exporter (`otlp` or `none`)
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://localhost:4317` | OTLP collector gRPC endpoint
|===

== Health Endpoints

|===
| Path | Description

| `GET /healthz` | Liveness — returns 200 if the process is up
| `GET /readyz` | Readiness — returns 200 if a `SELECT 1` against the database succeeds
|===

Use `/readyz` as the Kubernetes readiness probe and `/healthz` as the liveness probe. A failing `/readyz` indicates a lost database connection — check PostgreSQL availability and `JDBC_URL`.

== Startup Dependencies

The service fails to start if the database is unreachable. In the root Docker Compose stack the startup order is enforced via:

[source,yaml]
----
depends_on:
  liquibase-measures:    # schema migrations applied first
    condition: service_completed_successfully
  pg-seed:               # seed data inserted after migrations
    condition: service_completed_successfully
  keycloak:              # JWT verification endpoint must be reachable
    condition: service_started
----

If `liquibase-measures` fails (e.g. migration conflict), `measures-backend` will not start.

== Database

The service uses PostgreSQL. Schema is managed exclusively by the `liquibase-measures` container using migrations in `src/main/resources/db/changelog/`. The application role is DML-only (no DDL permissions).

=== Schema

* `measures` — stores all measurement records

|===
| Column | Type | Notes

| `id` | UUID PK | Generated by the service
| `user_id` | UUID | References Keycloak user (no FK — users table not co-located)
| `type` | TEXT | `CGM`, `BGM`, `BLOOD_PRESSURE`, `WEIGHT`, `PULSE`
| `source` | TEXT | `MANUAL`, `NIGHTSCOUT`, `GOOGLE_FIT`, `APPLE_HEALTH`
| `data` | JSONB | Measurement payload; structure varies by type
| `measured_at` | TIMESTAMPTZ | When the measurement was taken
| `created_at` | TIMESTAMPTZ | Insertion timestamp
| `status` | TEXT | `ACTIVE` or `ARCHIVED`
|===

=== Data Retention

Records are never physically deleted. Deletion is soft: `status` is set to `ARCHIVED`. Archived records are excluded from all read queries by default. The EU MDR requirement is 7-year audit log retention — do not purge rows from the `measures` table.

=== Bulk Insert Limits

CGM devices (via kdiab-nightscout) may batch-insert up to 100 readings per request. Inserts above this limit are rejected with `400 Bad Request`. If a CGM device sends a full historical backfill, the client must paginate requests.

== Scaling

`kdiab-measures` is **stateless at the application layer** — all state is in PostgreSQL. It can be scaled horizontally. Ensure the PostgreSQL connection pool (`DB_POOL_SIZE`) is sized to the total number of application instances × pool size stays within PostgreSQL's `max_connections`.

Resource limits per instance (from `docker-compose.yml`): 512 MB RAM, 1 CPU.

== Structured Logging

All logs are emitted as JSON to stdout. Key fields:

* `level`, `timestamp`, `message`
* `Correlation-ID` — from `X-Correlation-ID` header or generated on ingress
* `userId` — present in service-layer log entries

Log level default: `INFO`. To enable `DEBUG` temporarily, set the logback level via JVM system property (`-Dlogback.configurationFile=...`) or restart with a modified `logback.xml`.

== Common Operations

=== Query a user's recent CGM readings

[source,bash]
----
curl -s http://localhost:8080/api/v1/users/$USER_ID/measures \
  -H "Authorization: Bearer $TOKEN" \
  -G -d "type=CGM" -d "page=0" -d "size=20" | jq .
----

=== Archive a specific measure

[source,bash]
----
curl -X DELETE http://localhost:8080/api/v1/users/$USER_ID/measures/$MEASURE_ID \
  -H "Authorization: Bearer $TOKEN"
----

Returns `204 No Content`. The record is soft-deleted (status → `ARCHIVED`).

== Troubleshooting

=== Service fails readiness check (`/readyz` returns 500)

1. Confirm `JDBC_URL`, `DB_USER`, `DB_PASSWORD` are correct.
2. Check that the `kdiab-measures` PostgreSQL database exists and the user has SELECT/INSERT/UPDATE privileges.
3. Check for PostgreSQL connectivity: `psql $JDBC_URL -U $DB_USER -c "SELECT 1"`.

=== Liquibase migration conflict on startup

If `liquibase-measures` exits non-zero, check its logs for the conflicting changeset. A partial migration leaves the `DATABASECHANGELOGLOCK` table locked:

[source,sql]
----
DELETE FROM DATABASECHANGELOGLOCK;
----

Then re-run the `liquibase-measures` container.

=== High memory usage

Each CGM reading's `data` JSONB payload is kept in memory during request processing. If bulk imports cause OOM errors, reduce the batch size on the sending device or scale the container memory limit.
