## Project Overview

**kdiab-profiles** is the T1D basal pump profile manager. It allows patients, doctors, and admins to manage insulin pump basal profiles (basal rates, ICR, ISF, and blood glucose targets) with a copy-on-write state machine and doctor-patient collaboration workflow.

## Profile State Machine (ProfileService)
- DRAFT → ACTIVE (activate)
- ACTIVE → ARCHIVED + new ACTIVE (copy-on-write on update or activation)
- PROPOSED → ACTIVE (patient accepts) or ARCHIVED (patient rejects)
- Active profiles are **immutable** — any update archives the current and creates a new ACTIVE version linked via `previousProfileId`. Clients will receive a **new profile ID** in the response — local state references must be updated.

## Domain Validation
Clinical safety checks live in `Profile.validate()` in the domain model (not the service layer): max daily basal 150 U/day, ICR/ISF range checks, unit heuristics.

## Database Notes
PostgreSQL is required for production. The `IDX_PROFILES_USER_ACTIVE` partial index (`WHERE status = 'ACTIVE'`) enforcing one active profile per user is defined with `dbms: postgresql` in the Liquibase changeset — not created in H2. Integration tests use H2 in-memory.

## Key Design Decisions (ADRs)
- **ADR-015 — Copy-on-Write profiles**: Active profiles never mutated in place. Every update archives current + creates new ACTIVE version.
- **ADR-016 — Doctor-Patient collaboration via PROPOSED status**: Doctors can only create PROPOSED profiles; patients must accept/reject. Prevents doctors from directly modifying active treatment profiles.
- **ADR-105 — Kotlin-native types in domain layer**: `kotlin.uuid.Uuid`, `kotlinx.datetime.Instant`/`LocalTime` in domain. Infrastructure layers handle mapping to Java types for Exposed/Ktor.
- **ADR-302 — No Users table**: `userId` stored directly as UUID in profiles table. Identity comes entirely from Keycloak JWT claims.
- **ADR-303 — JWT/RBAC**: Roles from Keycloak `realm_access.roles`. Frontend parses roles from raw JWT access token.
- **ADR-110 — Correlation ID tracing**: `X-Correlation-ID` generated by frontend Axios interceptor, extracted/generated by backend `CallId` plugin, bound to SLF4J MDC.
- **ADR-111 — Conventional Commits + Semantic Release**: Angular format; Semantic Release on `main` determines version bumps and creates GitHub releases.
