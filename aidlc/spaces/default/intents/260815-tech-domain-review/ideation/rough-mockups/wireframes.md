# Wireframes — Technology & Domain Review

**Status: NOT APPLICABLE**

> Consulted: `intent-statement.md`, `scope-document.md`, `intent-backlog.md`.

This initiative produces **recommendations** (a prioritized GitHub-issue backlog, quick-wins, a phased
roadmap), not user-facing features. No new screens, components, or flows are being designed, so there is
nothing to wireframe.

## If UI work emerges later

Should the review surface a *frontend* recommendation (e.g. one of the `MA-5` kdiab-ui items) that grows
into its own feature, that feature would start a **new intent** and run its own Rough/Refined Mockups then.
The "output format" of this review is documents, not an interface.

## Presentation format of the review output (the only "layout" decision here)

- **GitHub issues** — one per finding, labelled by theme + severity, evidence-linked.
- **Roadmap document** — phased (near / mid / long), value-density ordered.
- **Quick-wins list** — a short actionable subset.

No visual design required.
