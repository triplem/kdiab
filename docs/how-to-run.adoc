= How to Build and Run kdiab
:toc: left
:icons: font

This guide covers building, testing, and running the full kdiab platform locally.
All commands are run from the repository root unless noted otherwise.

== Prerequisites

* *JDK 21* (e.g. Eclipse Temurin)
* *Node.js LTS* + npm
* *Docker* or *Podman* with a compose plugin

== Building

Two build orchestrators are available at the repo root:

* `./gradlew` — the primary orchestrator for build and test; integrates with IDEs and uses
  Gradle's incremental build and build cache.
* `build.sh` — retained for Docker-specific workflows (`--docker`, `--clean`).

=== Gradle (primary)

The root Gradle project is a composite build that includes all four services. Each service
remains independently buildable via its own `./gradlew`.

[source,bash]
----
./gradlew build    # build all backends (Kotlin/Ktor) and all frontends (npm) — parallel
./gradlew check    # build + all tests + Detekt + Kover (80% gate) + frontend lint/test
./gradlew clean    # remove all build outputs and frontend/dist directories
----

Individual subprojects and tasks can be targeted directly from the root:

[source,bash]
----
./gradlew :kdiab-bff:backend:build
./gradlew :kdiab-measures:backend:check
./gradlew :kdiab-profiles:buildFrontend
----

TIP: IntelliJ IDEA — open the root `settings.gradle.kts` to import all four services as modules
with full cross-service navigation and refactoring support.

=== build.sh (Docker and clean)

`build.sh` is the monorepo build orchestrator for Docker image builds and full environment resets.
It logs per-service output to `.build-logs/`.

=== Available Flags

[cols="2,3"]
|===
| Flag | Effect

| _(none)_         | Build all backends (`:backend:build`) and all frontends
| `--check`        | Build + run all tests, Detekt, Kover (80% coverage gate)
| `--backend-only` | Gradle builds only, skip npm
| `--frontend-only`| npm builds only, skip Gradle
| `--docker`       | Build all Docker images (service + liquibase migration images)
| `--no-parallel`  | Sequential execution — useful when disk / RAM is tight
|===

Flags are composable:

[source,bash]
----
./build.sh                   # build everything, skip tests
./build.sh --check           # build + full test suite
./build.sh --check --docker  # test + build Docker images
./build.sh --no-parallel     # sequential build (saves RAM)
----

=== What `--docker` Builds

`--docker` calls `docker compose build` (or `podman compose build` when Docker is not available)
for every image defined in the root `docker-compose.yml` that has a local `build:` context:

[cols="2,2,3"]
|===
| Compose service | Image name | Dockerfile

| `liquibase-measures`   | `localhost/kdiab-measures-liquibase:latest`   | `kdiab-measures/backend/Dockerfile.liquibase`
| `liquibase-profiles`   | `localhost/kdiab-profiles-liquibase:latest`   | `kdiab-profiles/backend/Dockerfile.liquibase`
| `liquibase-treatments` | `localhost/kdiab-treatments-liquibase:latest` | `kdiab-treatments/backend/Dockerfile.liquibase`
| `measures-backend`     | `localhost/kdiab-measures-backend:latest`     | `kdiab-measures/backend/Dockerfile`
| `measures-frontend`    | `localhost/kdiab-measures-frontend:latest`    | `kdiab-measures/frontend/Dockerfile`
| `profiles-backend`     | `localhost/kdiab-profiles-backend:latest`     | `kdiab-profiles/backend/Dockerfile`
| `profiles-frontend`    | `localhost/kdiab-profiles-frontend:latest`    | `kdiab-profiles/frontend/Dockerfile`
| `treatments-backend`   | `localhost/kdiab-treatments-backend:latest`   | `kdiab-treatments/backend/Dockerfile`
| `treatments-frontend`  | `localhost/kdiab-treatments-frontend:latest`  | `kdiab-treatments/frontend/Dockerfile`
| `bff-backend`          | `localhost/kdiab-bff-backend:latest`          | `kdiab-bff/backend/Dockerfile`
| `bff-frontend`         | `localhost/kdiab-bff-frontend:latest`         | `kdiab-bff/frontend/Dockerfile`
|===

Externally pulled images (`postgres`, `keycloak`, `pgadmin`) are not rebuilt by this flag.

NOTE: `--parallel` is only passed to `docker compose build`. `podman compose` manages concurrency
internally and does not accept that flag.

Build logs land in `.build-logs/docker images.log` on failure.

== Running the Full Platform

The root `docker-compose.yml` starts the entire platform: all four services, Keycloak, PostgreSQL,
pgAdmin, Liquibase migrations, and a seed-data job.

=== Container Lifecycle

[source,bash]
----
# First run — build images then create and start containers
./build.sh --docker
podman compose up -d          # -d runs detached (background)

# Subsequent runs — start already-created containers
podman compose start

# Stop without removing containers
podman compose stop

# Remove containers (images are kept; next start requires `up` again)
podman compose down

# Remove containers AND volumes (wipes database and pgAdmin state)
podman compose down -v
----

NOTE: `podman compose start` only works on *existing stopped* containers. Always run
`podman compose up -d` first. After `podman compose down`, run `up -d` again before `start`.

Equivalent commands with Docker:

[source,bash]
----
docker compose up -d
docker compose start
docker compose stop
docker compose down -v
----

=== Database Initialisation

The database is initialised automatically in three steps:

1. `config/postgres/01-init-databases.sh` — creates `kdiab-measures`, `kdiab-profiles`,
   and `kdiab-treatments` databases on first Postgres startup.
2. `liquibase-measures` / `liquibase-profiles` / `liquibase-treatments` — run schema migrations.
3. `pg-seed` — inserts 30 days of realistic CGM, treatment, and profile data for `sarah` and `mike`.

== Running a Single Service

Each service has its own compose file for standalone development:

[source,bash]
----
cd kdiab-<service>
docker compose up --build          # service + its own Keycloak + Postgres
docker compose down -v

# With pgAdmin
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build

# Podman
./manage-podman.sh start
./manage-podman.sh cleanup
----

== Running Components Without Docker

=== Backend (Kotlin / Ktor)

Requires a running PostgreSQL instance and a Keycloak server (use the per-service compose for these).

[source,bash]
----
cd kdiab-<service>
./gradlew :backend:run
----

=== Frontend (React / TypeScript)

[source,bash]
----
cd kdiab-<service>/frontend
npm install
npm run dev          # dev server on port 3000, proxies /api to backend on 8080
----

== Running Tests

=== All Services

[source,bash]
----
./gradlew check        # preferred: tests + Detekt + Kover + frontend lint/test, all services
./build.sh --check     # alternative: same scope via shell orchestrator
----

=== Single Service

[source,bash]
----
cd kdiab-<service>
./gradlew :backend:test              # unit tests
./gradlew :backend:integrationTest   # integration tests
./gradlew :backend:e2eTest           # E2E tests
./gradlew :backend:check             # all tests + detekt + kover
----

[source,bash]
----
cd kdiab-<service>/frontend
npm run test                         # Vitest unit tests
npx playwright test                  # E2E tests (requires running app)
----
