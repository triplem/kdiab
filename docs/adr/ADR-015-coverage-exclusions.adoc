= ADR-015: Frontend Coverage Exclusions and Threshold Strategy
:toc: left
:icons: font

* *Status*: Accepted
* *Date*: 2026-05-26
* *Deciders*: triplem

== Context

`kdiab-ui` enforces test coverage via Vitest + v8 with `thresholds` configured in `vite.config.ts`.
The project quality gate (`docs/quality-gates.md`) mandates ≥ 80% coverage.

A blanket 80% requirement applied to all source files would require extensive test suites for
components whose correct behaviour is fundamentally observable only at the integration level —
specifically those that render third-party chart libraries (Recharts), compose authentication flows,
or act as thin adapters over generated code.
Forcing unit-level stubs of these components produces tests that test the mocks rather than the
product and that break on every library upgrade without providing safety coverage.

The following categories of files are deliberately excluded from coverage measurement.

=== Generated code

`src/api/generated/**` — TypeScript clients generated by `openapi-generator`. Generating tests for
generated code provides no safety benefit and breaks on every API regeneration.

=== Thin API adapters

`src/api/analyzeApi.ts`, `measuresApi.ts`, `profilesApi.ts`, `treatmentsApi.ts`, `carbsApi.ts`,
`usersApi.ts` — single-function wrappers that call the generated client with typed parameters.
No business logic is present; the generated client is tested by the generator's own test suite.

=== Composition root

`src/App.tsx` — Top-level tab router, OIDC auth rendering, and role guards.
Correct behaviour requires a running OIDC provider and real browser navigation; this is covered by
Playwright E2E tests (`npm run test:e2e`). Mock-based unit tests of `App.tsx` are present in
`App.test.tsx` and cover specific scenarios (feature flags, auth error rendering, logout), but full
branch coverage is impractical at unit level.

=== Recharts rendering components

`src/features/dashboard/DashboardView.tsx`,
`src/features/dashboard/GlucoseTrendChart.tsx`,
`src/features/dashboard/BasalRateChart.tsx`,
`src/features/analytics/BolusAvgChart.tsx` —
These components contain almost no business logic; all clinical calculations live in separately
tested utility modules (`basalUtils.ts` at 98% coverage, `tooltipFormatter.ts` at 100%,
`insulinHourlyUtils.ts` at 93%).
The rendering itself (tooltip callbacks, custom dot shapes, scale formatting) is only reachable
through unmocked Recharts internals.
Attempting to invoke these paths requires either a real DOM with canvas support or complex mocking
that couples tests to Recharts' internal component tree.

=== Data-fetching hooks

`src/features/dashboard/useDashboardData.ts` — Pure `useQuery` orchestration with no transformation
logic. The hook's correctness is verified implicitly by the component tests that mock the React
Query layer and by E2E tests that exercise the full stack.

=== Boilerplate

`src/main.tsx`, `src/vite-env.d.ts`, `src/i18n/**` — Entry-point bootstrapping and type
declarations; no testable logic.

=== Treatment sub-forms

`src/features/treatments/forms/**` — Thin UI adapters that render form fields for each treatment
type. Business-logic validation is tested through `AddTreatmentModal.test.tsx` which exercises the
full form submission path.

== Decision

Maintain the exclusion list above.
Set coverage thresholds to enforce no regression on the *included* code, at levels that reflect the
actual measured coverage of non-excluded files.

.Coverage thresholds in `vite.config.ts`
[cols="1,1,1"]
|===
| Metric | Previous threshold | New threshold

| Statements | 68 | 72
| Branches   | 57 | 59
| Functions  | 60 | 63
| Lines      | 70 | 74
|===

These values are derived from the measured coverage of included files at the time this ADR was
written and serve as a regression gate.
New code added to non-excluded files must maintain or improve these numbers; if coverage drops
below threshold the CI build fails.

The gap between these thresholds and the project 80% quality gate is intentional and documented
here as an accepted deviation for the excluded categories.
If any excluded category becomes feasible to test (e.g. a Recharts upgrade provides testing
utilities), the exclusion should be removed and the threshold raised.

== Consequences

* CI prevents regression in covered code.
* Developers adding new features to excluded files must ensure the feature's logic is extracted
  into a tested utility module (following the `basalUtils.ts` pattern).
* The 80% quality gate is met for all non-excluded, non-trivial logic.
* Clinical business logic (dose calculator, TIR, HbA1c, AGP, alarm thresholds) is all in
  non-excluded files and is covered at > 80%.

== Alternatives Considered

=== Raise thresholds to 80/75/80/80 without exclusions

Achieving 80% branches/functions on excluded files would require:

* Mocking the Recharts rendering pipeline (fragile, library-version coupled)
* Simulating full OIDC flows in unit tests (slow, brittle)
* Generating tests for generated code (circular, no safety value)

This approach was rejected because the resulting tests would be maintenance burdens that provide
no clinical safety benefit.

=== Remove thresholds entirely

Rejected. Without a threshold gate, coverage regressions are invisible in CI.
A threshold set to current measured values catches regressions while not blocking legitimate
development on difficult-to-cover infrastructure files.
