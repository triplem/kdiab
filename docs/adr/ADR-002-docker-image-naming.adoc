= ADR-002: Docker Image and Container Naming Convention
:toc: left
:icons: font

* *Status*: Accepted
* *Date*: 2026-05-02
* *Deciders*: triplem

== Context

The root `docker-compose.yml` defines 11 buildable images (service backends, service frontends,
and Liquibase schema migration runners) and 15 containers in total (including pulled infrastructure
images). Without explicit `image:` and `container_name:` fields, `podman compose` / `docker compose`
derives both names from `<project_name>_<service_name>`, where `project_name` is the name of the
current working directory at the time the command is run.

This caused two problems:

* Images built by `build.sh --docker` (run from repo root, project `kdiab`) had names like
  `kdiab_measures-backend`, which differed from images built from inside a service directory
  (project `kdiab-measures`) that had names like `kdiab-measures_backend`.
* `podman compose start` looked for containers named `kdiab_liquibase-profiles_1` etc. — names
  that were never created because `podman compose up` had not been run, and even when it had been,
  the `_1` suffix and project-derived prefix made the names unpredictable.

== Decision

Add explicit `image:` tags to every service with a `build:` context, and `container_name:` tags
to every service in `docker-compose.yml`. Both follow the same fixed pattern:

----
kdiab-<service>-<function>
----

Where:

* `<service>` is one of: `measures`, `profiles`, `treatments`, `bff`
* `<function>` is one of: `backend`, `frontend`, `liquibase`

Image names carry the `localhost/` registry prefix; container names do not:

[source,yaml]
----
measures-backend:
  container_name: kdiab-measures-backend
  image: localhost/kdiab-measures-backend:latest
----

Infrastructure services that use pulled images follow the simpler `kdiab-<component>` pattern
(`kdiab-postgres`, `kdiab-keycloak`, `kdiab-pgadmin`, `kdiab-pg-seed`).

Externally pulled images (`postgres`, `keycloak`, `pgadmin`) are unaffected — they already have
explicit `image:` tags pointing to public registries.

== Build and Run Workflow

Images are built via `build.sh --docker`, which calls `podman compose build` (or `docker compose build`)
on all 11 services. The compose tool reads the `image:` tag from `docker-compose.yml` and stores the
result under that fixed name regardless of the working directory.

Container lifecycle:

[source,bash]
----
./build.sh --docker          # build / rebuild images
podman compose up -d         # create containers and start (first time, or after down)
podman compose stop          # stop running containers (containers still exist)
podman compose start         # start stopped containers (requires prior `up`)
podman compose down          # stop and remove containers
podman compose down -v       # also remove volumes (wipes database)
----

`podman compose start` only works on *existing* stopped containers. Run `podman compose up -d`
first to create them.

== Consequences

=== Positive

* `podman compose up` always finds the images built by `build.sh --docker`, regardless of where
  either command is invoked.
* Image names are predictable and grep-able across `docker-compose.yml`, `build.sh`,
  and documentation.
* Stale images from previous directory-derived naming (e.g. `kdiab_measures-backend`) can
  be safely pruned with `podman image prune`.

=== Negative

* If a new service or function is added, both the `image:` tag in `docker-compose.yml` and
  the `DOCKER_SERVICES` array in `build.sh` must be updated consistently.

== Alternatives Considered

=== Rely on compose project name (`--project-name`)

Pass a fixed `--project-name kdiab` to every compose invocation. Rejected: this requires every
developer and every CI script to remember the flag; one missing invocation reverts to the
directory-derived name.

=== Use a `.env` file with `COMPOSE_PROJECT_NAME`

Set `COMPOSE_PROJECT_NAME=kdiab` in a root `.env`. Partially equivalent to explicit `image:`
tags but less explicit — the image name is still derived (`kdiab_measures-backend`) rather than
stated, and the `.env` is optional and easy to miss.
